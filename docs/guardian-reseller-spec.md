# Claude Guardian 代理售卖设计与实施记录

版本：v0.3，2026-11-09。保留 v0.2 的整单结算及退款规则，新增第 11 节已确认、尚未实现的独立店铺设计。本地基线为 `249e5b3be`，本次不包含生产部署。

## 1. 已确认的业务规则

- 平台收客户款；平台负责交付、联系客户及售后。代理不获得客户联系方式、凭据或内部交付备注。
- 覆盖现有全部 Guardian 商品类型：部署、Mac mini 月／季／年付、MAX／Ultra 首月加购。未配置或下架的规格不会自动开售。
- 单层代理。管理员给现有用户开通资格，代理不能发展下级代理、管理其他代理或进入管理员后台。
- 管理员设置供货价，代理设置自己的零售价。代理赚取差价并承担正常订单的收款手续费。
- 沿用 Epay；管理员配置实际商户费率用于预估，每笔已付款订单须核对实际手续费后才能提现。不把讨论中的 0.6% 当作已核验费率或支付宝官方固定费率。
- **整单结算，没有分期、月度释放、商品项分摊。** 交付满 7 天且实际手续费核对完成后，该订单收益进入可提现金额。
- **所有代理订单退款均向客户扣除渠道实际未退手续费，没有平台履约问题例外。** 仅整单退款；退款后代理差价归零，不重复向代理扣同一笔收款手续费。
- 人工支付宝打款，最低申请 1 元；打款费由代理承担，从申请金额中扣除。平台先核实收款人。
- 禁止代理购买自己销售的商品。
- 资格、收益及提现独立于 API 钱包和充值邀请返佣。

## 2. 代理身份、入口及权限

数据库定义为普通 `User` 对应一条 `GuardianReseller`，以用户 ID 唯一，不改变原账号角色、分组、登录方式及 API 权限。

| 状态 | 能力 |
| --- | --- |
| 无代理记录 | 普通客户权限；不能使用代理接口 |
| active | 设置已授权商品售价，使用专属入口销售，查看自己的经营记录，申请提现 |
| suspended | 禁止新销售与改价；保留自己的历史订单、收益及符合条件的提现 |

管理员在「用户管理 → Guardian 代理资格」开通／暂停，填写原因。操作人、时间、前后状态记入资格事件。

代理中心：`/guardian/reseller`。登录后有资格才显示入口；直接访问未开通账号显示说明，后端仍强制资格校验。

专属销售入口：`/guardian/services?reseller=<随机代理码>`。支持商品分类、周期与登录返回参数；不使用跨页面永久归属 Cookie。此入口与直营商品目录使用不同查询缓存。

上述为当前默认入口；代理自助绑定域名后的独立店铺规则见第 11 节，不代表当前已经支持域名绑定。

代理可查看自己的供货价、售价、订单号、商品、成交金额、手续费、收益及交付状态。不能读其他代理数据、客户联系方式、客户备注、内部交付备注、账号密钥；公开销售页只提供零售价。

全部新增经营与管理接口仅允许面板登录会话，不接受个人访问令牌。管理员接口另有管理员权限检查；写接口复用站点来源校验与请求体限制。

## 3. 商品与报价

每个「代理 × 商品」记录一份授权及报价：

- 供货：单次／月付、季付、年付、MAX／Ultra 首月加购；管理员维护。
- 零售：对应四项价格、是否上架；代理维护。
- 可选规格为 0 表示未开放，不代表免费。
- 商品下架、代理暂停、授权撤销、当前零售价不能覆盖成本，均阻止新购。
- 最低售价：零售价 ≥ 供货价 + 预计收款手续费。
- 预估手续费按费率计算并向上取整到分；这是保守预估，不是对渠道实际舍入规则的假定。
- 金额以整数分存储；费率以万分位存储（60 = 0.60%）。

下单由后端读取商品和报价，校验客户端展示总额；变价后须刷新确认。订单保存实付、供货总额、MAX／Ultra 各自的供货额、费率、预估手续费、代理和退款条款版本。旧订单不随新价格改变。

代理订单仅提供支付宝，客户必须确认退款扣费条款。续费转直营另须明确确认。订单沿用现有两小时待支付有效期；真实有效的迟到支付通知仍按原订单快照处理，不改成新报价。

## 4. 订单与续费归属

### 新购

从 A 的专属入口独立新购归 A；从 B 入口新购归 B；直营入口独立新购归直营。不因浏览或以前购买而永久绑定客户。

### 持续服务

Mac mini 首次交付创建一条客户服务记录，区别于商品目录 ID。记录客户、商品、首单与当前续费代理。后续订单关联该服务，服务所有权由后端验证。

「我的订单」中提供「我的服务与续费」；服务器取得原服务归属和当前有效报价。客户端传入另一代理码不能改变续费归属。月付改季／年付仍属同一服务。

本阶段不提供管理员手动变更未来续费归属功能。已有订单及历史收益不改写。

原代理暂停时，客户须确认平台直营报价。对应直营续费实际付款后，未来归属转为直营；代理恢复不自动抢回。没有有效报价则联系平台，不自动使用旧价。

一次性部署复购按新购处理。MAX 和 Claude Ultra 均为首月加购，只能二选一，也可都不选；随托管订单一次性收费，月／季／年付均不重复乘以月数。后续订阅续费单独处理，不自动扣费。商品和订单分别保存两种加购的价格；代理各自配置供货价与售价。价格均为人民币，不展示固定美元金额。新增商品表单中 Ultra 初始价格为 ¥2500，管理员可修改或留空关闭；已有商品不自动开售，需管理员先配置。

## 5. 资金口径

正常订单：

```
净收益 = 实付金额 - 供货金额 - 实际收款手续费
```

预估用于未核对账单的待结算展示；实际手续费须有账单凭证。核对确认后不直接覆盖原账目。

| 金额 | 定义 |
| --- | --- |
| 待结算 | 已付款但未满足交付等待期或手续费核对条件的收益 |
| 可提现 | 符合条件的净收益，减去已提现、提现预留及退款冻结 |
| 提现预留 | 待审核与打款处理中的申请金额 |
| 退款冻结 | 满足结算条件但正在退款处理的收益 |
| 已提现 | 已成功打款的申请总额，包含代理承担的打款费 |
| 待追回 | 退款等冲减后，已有成功打款超出保留收益的部分 |

已提现订单后来退款，原收益撤销；已付给代理的金额形成待追回金额，后续收益先抵扣。未实际完成的退款只冻结收益，不直接记成确定欠款。

## 6. 整单退款

1. 管理员先确认订单已付款并核对实际收款手续费。
2. 先处理该代理尚未完成的提现申请，避免资金已预留或打款结果不明时重新分配。
3. 发起退款，冻结该订单收益。
4. 在支付渠道／人工操作实际退款。
5. 核实外部成功结果、渠道退回手续费和退款凭证后登记完成；界面显示待确认的客户实际退款金额。
6. 若未实际退款，可以取消处理中记录；已完成记录不能再次退款。

```
客户实际退款 = 原实付 - 实际收款手续费 + 渠道退回手续费
代理最终收益 = 0
```

例：实付 260 元、实际手续费 1.56 元且渠道未退手续费，则退客户 258.44 元。代理收益归零；已经提现的代理收益需追回，不再额外扣 1.56 元。

代理订单不能通过原订单状态下拉框绕过此流程。上述退款按钮登记资金结果，不会调用 Epay 发起退款。客户条款、代理账目和管理员核对界面使用同一口径。

## 7. 提现

申请填写金额、支付宝账号及姓名；复用既有安全验证（已启用 MFA／Passkey 时不降级为密码）。验证凭据绑定本次金额、收款账号、姓名、申请标识和当前会话，单次消费。客户端取消验证不会生成申请或显示成功。

`pending → processing → paid / failed`；`pending → rejected / cancelled`。

- pending：金额已预留；代理可以撤销，管理员可以拒绝或核实收款人后进入处理。
- processing：管理员填写打款费；实际打款 = 申请金额 − 打款费，必须大于零。代理不能撤销。
- paid：人工打款成功后凭外部交易号登记；同一外部凭证不能重复记账。
- failed：核实外部失败后释放预留。结果不明必须维持 processing，不能当成失败重付。
- 每个代理的申请标识唯一；相同内容重试返回已有申请，不能重复占用余额；相同标识改变金额／收款人被拒绝。

提现与退款事务对同一代理资金记录串行处理，使用项目已有跨数据库锁辅助函数。没有新增支付网关自动出款、钱包互转或分期调度器。

## 9. 尚未确定或不在本次自动化范围

以下不能视作已配置上线：

1. **商户实际费率与渠道退费规则**：须由管理员核实商户协议和真实账单；程序没有预填正式费率。
2. **正式代理名单、每位代理的供货价、销售价、可售规格**：需要业务人员配置。
3. **历史持续服务录入与到期管理**：历史订单不自动补绑代理、不追溯返利。新版本交付创建服务记录；设备、租期起止、暂停补时、终止回收仍由平台实际履约记录决定，本次没有自动到期／设备管理。
4. **独立 MAX／Ultra 续订、换机或跨商品升级**：现有商品没有这些完整履约定义，未自行增加。
5. **已确认手续费纠错及线下追回欠款登记**：第一版核对后不可直接覆盖；退款欠款可用未来收益抵扣。复杂人工调整仍需另定规则及审计入口。
6. **收款及人工退款／打款验收口径（2026-11-09 用户确认）**：此前已上线版本的真实 Epay 收款已验收通过，本次沿用，不要求重复验收。退款及支付宝打款均由人工操作，不增加实款演练作为本次上线门槛。系统内既有的实际手续费核对、凭证登记及防重复记账规则保留。本轮本地测试没有执行真钱交易。
7. 新界面提供中英文文案，其他语言暂回退英文。

## 11. 独立店铺与自助域名绑定（已确认设计，尚未实现）

### 代理操作流程

1. 代理在代理中心填写店铺名称与自己持有的域名，无需平台逐个代填。
2. 页面提供该域名所需的 DNS 记录名称、类型和值，代理在自己的域名服务商处配置。
3. 代理点击验证；平台核验域名归属与解析。只有验证通过且 HTTPS 就绪后，店铺域名才能启用。保存表单不等于开通成功。
4. 启用后，代理中心明确展示完整 HTTPS 销售链接并提供复制入口。
5. 未绑定域名时，继续提供现有默认销售链接；在代理中心提示默认链接会展示平台域名，该提示不放在客户销售页。

第一版每个代理绑定一个域名，同一域名不能同时属于两个代理。更换域名需重新验证，不改写原订单、收益或持续服务续费归属。此能力仅用于代理自己的店铺，不开放其他代理的设置权限。

### 客户页面与跳转

- 店铺展示代理设置的店名，店铺首页入口返回本店商品目录。
- 商品、登录、我的订单与服务续费保持在店铺内；不提供返回主站直营目录、平台后台或代理中心的导航入口。
- 客户页不显示“当前为代理销售入口”等提示条；平台仍负责实际收款、交付及售后，代理仍不获得客户联系方式。
- 店铺的代理身份由服务端按已启用域名确定，不能靠客户修改 URL 参数切换店铺报价或成交归属。
- 店铺新购按该店铺代理归属；同一持续服务续费仍按第 4 节确定的原归属及暂停后转直营确认规则处理。店铺域名不产生永久客户绑定，不改变跨店独立新购规则。
- 保留项目政策要求的 new-api / QuantumNous 署名。付款页面可能显示平台商户名称，不承诺完全隐藏平台身份。

### 实现前需要落实的技术事项

这些是平台侧接入工作，不要求代理预先向开发者提供第一家店铺的域名：

- 确定统一 DNS 接入目标、域名归属验证记录及 HTTPS 证书的签发和续期方式；表单中不得展示尚不存在的解析目标。
- 确定独立域名内可用的登录方式、会话范围、支付返回和订单查询路径。复用现有账号体系；不因切换域名放宽现有认证要求，也不直接跨域传递会话凭据。涉及认证实现前须完成仓库要求的 OWASP 阅读及验证。
- 确定域名更换、解绑后的旧入口提示及证书处理方式；未验证或未启用的域名不得落入主站直营目录。
- 正式 DNS、证书和生产接入尚未配置。本节仅记录设计，不属于前述测试已经覆盖的实现。

### 后续验收范围

- 代理保存店铺设置、复制 DNS 记录、查看待验证／HTTPS 准备中／已启用状态及失败原因；域名更换后重新验证。
- 两家代理的域名分别展示各自店名与零售价，修改查询参数不能切换服务端店铺身份；不向客户返回供货价或其他代理后台数据。
- 从商品到登录返回、下单、支付返回、我的订单和续费的完整路径保持正确店铺上下文；订单访问仍受客户所有权限制。
- 验证未配置域名的默认链接仍可使用，以及独立店铺没有主站直营导航。验证原有结算、退款、提现与续费归属规则没有变化。
